# 17 · Repository, determinism policy, hashes, replays and CI

Model: Opus 5.5 (determinism and hashing touch every rule) · Effort: high · Depends on: nothing; runs first · Branch: `item/17-repo-determinism-ci` · Works in `games/hoard/` of the `gamedev` repo; also touches the repo root's `.gitattributes`, `.gitignore` and `.github/`

Corrected 2026-10-26 after the code audit (`audit-2026-10-26.md`): the repository is `gamedev` with the game in `games/hoard/`; the runner is called `ages`; the sim takes 0.3 to 1 s per 3000 years, not 10 ms; the input audit of point 6 has its answer; the old Blueprint-only `Hoard/` project is removed.

This is the item the owner asked for on 2026-10-23 (GitHub repo, one branch per item, review and merge) made concrete, plus the determinism and replay machinery every later item and every bug report will stand on. Most of it is tooling; the sim changes are small and audited, and exactly one golden regeneration is expected (own `pow`).

## Goal

A repository an agent can clone and work in from a brief; a determinism policy the build enforces; a state hash with a trace that finds the first divergent decade; a save header that can be migrated; a replay file that reproduces a run from `(seed, data, act log)` and verifies itself; and a CI that proves, on every push, that GCC, Clang, MSVC and wasm32 agree with each other and with the committed goldens.

## Scope

1. **Layout.** Keep the existing tree under `games/hoard/` (`sim/`, `data/`, `web/`, `tools/`, `assets/`, `art/`, `prototype/`) and add: `docs/` (the design docs this item and the next ones read, copied from the Project with the same names), `rt/` (a README saying what goes there: the real-time core, no engine headers; item 18 fills it), `tests/golden/` (the two existing hash files move here), `tests/saves/`, `tests/replays/`, `reports/`, and at the repo root `.github/workflows/`. Remove `games/hoard/Hoard/` (a Blueprint-only project with nothing in `Content/`; item 18 starts fresh in `unreal/Hoard/`). Rename the runner target from `ages` to `hoard-sim` and update the README, `tools/*.py` and `web/smoke.mjs`; the library target keeps its name. `.gitattributes` (repo root): add `*.gltf`, `*.bin`, `*.wav`, `*.ogg`, `*.uasset`, `*.umap` to LFS where missing, and `games/hoard/data/** text eol=lf`, `*.json text eol=lf`, `*.md text eol=lf`. `assets/LICENSES.md` lists every asset pack with its licence; the CC BY-SA placeholder dragon is marked "never in an outside build"; `art/redragon/redragon.blend` is marked "licence unknown". `.gitignore`: `build*/`, `out/`, editor junk.
2. **Determinism policy, enforced.** One CMake function `hoard_sim_flags(target)` applied to every target that compiles `sim/` (native, tests, wasm): GCC and Clang `-ffp-contract=off -fno-fast-math`; MSVC `/fp:strict`; wasm32 `-ffp-contract=off`, no `-msimd128`, no relaxed SIMD; a configure-time error if `-ffast-math`, `-Ofast` or `/fp:fast` appear in any flag variable. `tools/check_banned.sh` greps `sim/` for the banned list in the research doc §1 (every `<cmath>` function except `sqrt fabs floor ceil trunc round copysign`, `float`, `long double`, `<random>`, `std::shuffle`, `std::reduce`, `std::hash`, `rand`, `time`, threads, iteration over `unordered_*` that reaches state) and runs as a `ctest` test labelled `fast`. The audit found six `std::pow` (`hoard.cpp`, `talents.cpp`, `rules/memory.cpp` ×2, `rules/remnants.cpp`) and nothing else; replace them. `sim/core/detmath.{h,cpp}`: integer `pow` by squaring, `pow(x, 0.5)` by `sqrt`, otherwise `det::exp(y * det::log(x))` with the Horner versions from the research; designer curves that need other functions become tables in `data/` with linear interpolation. Environment guard at every API entry: rounding mode to-nearest and, on x86, the MXCSR flush bits clear; reset and count otherwise, the count visible in `world` as `fp_env_resets`. RNG rule: `world.rng` only, never two draws in one expression or argument list (a grep for `rng.next` twice on one line); keyed sub-streams `rng_for(seed, tag, id)` via splitmix64 are allowed and preferred for new rules.
3. **Hashing.** `sim/core/hash.h`: a `Hasher` with `u64`, `i64`, `f64` (bit pattern; −0 becomes +0; a non-finite value adds a counter instead of its bits), `str` (length first), `size` before every container, a tag constant per subsystem; splitmix64 mixing; never struct bytes. One `fields(F&)` per state struct feeds both the serialiser and the hasher so nothing is saved but unhashed. Parts in fixed order: rng, calendar and eras, factions, regions, people, relations and oaths, event log (count plus chain hash), lair and hoard; the root mixes the parts. `hoard-sim --trace out.jsonl` writes `{year, root, parts{...}}` per decade; `hoard-sim dump --seed S --year Y` writes sorted-key state JSON; `tools/first_div.py a b` prints the first differing year and part. Data hash: each `data/` file parsed, re-serialised with sorted keys and shortest round-trip numbers, hashed, then the sorted (path, hash) list hashed; exposed as `data_hash` in `world` and in every save and replay header.
4. **Goldens.** Two per case: the state hash (must match on every platform) and the chronicle text hash. `tests/golden/state_hashes.txt` holds 300 seeds × 3000 years (one line `seed hash`); `tests/golden/chronicle/` holds three seeds as text, one event per line (`year region type actor target magnitude cause`); `tools/chronicle_diff.py` prints the first changed line and the added and removed events by type. The six existing tests stay; `hoard-sim golden --seeds 1-300` is the command behind the hash file. Rule in `CLAUDE.md`: platforms must agree with each other before anything is compared with the committed goldens; a regeneration is its own commit beginning `golden:` with the chronicle diff pasted in.
5. **Save header and migrations.** Every save begins with the header from the research §3: `format`, `format_version` (1), `rules_version`, `build`, `data{root, scenario_bank{id, hash}, pattern_bank{id, hash}}`, `seed`, `year`, `acts`, `state_hash`. Loading reads the header first, refuses a newer `format_version` naming the build that wrote it, runs the (empty) `migrate[]` table for an older one, parses, checks invariants, recomputes `state_hash` and offers the previous autosave on mismatch. Writes go to a temp file, flush, atomic rename, one `.bak`. A save across `rules_version` loads and marks its embedded log `replay_verifiable: false`. Bank fields are reserved for item 10.
6. **Replays.** `.hrp` as gzipped JSON lines per the research §4: header line; one line per accepted input; a checkpoint line with the state hash after every `sleep`; an end line. The audit (§5) found ten state-changing API verbs, of which only `apply_acts` and `demand` write `World.acts`; `sleep` (its length), `pick_talent`, `accept_offer`, `decline_offer`, `answer_hook`, `kill_person`, `cast`, `terraform` and `load_world` do not. The `.hrp` records every one of them as a line (`i`, `y`, `t` = verb, its arguments, `answers`), and `replay` drives the same API. Item 09 later turns them into logged acts; until then the `.hrp` is the complete input record. Magnitudes are quantised to 1e-6 at the API boundary before they enter the log. Commands: `hoard-sim record --policy played --seed S --out run.hrp` and `hoard-sim replay run.hrp --verify` (exit code 3 and the first mismatching checkpoint on failure). `web/`: a "Report a problem" button in the sandbox that bundles the `.hrp`, the latest autosave and the build id as one base64 blob to the clipboard with a preview (no network); the page records its own `.hrp` from its API calls.
7. **CI.** `.github/workflows/hoard-ci.yml` at the repo root, `paths: games/hoard/**`, `working-directory: games/hoard`, checkout without LFS. On push and pull request: `native` matrix (ubuntu GCC, ubuntu Clang, windows MSVC) configures with `hoard_sim_flags`, builds, runs `ctest -L fast --output-on-failure --no-tests=error`, writes `hoard-sim golden --seeds 1-60` as an artifact (60 seeds on push, because one 3000-year run takes 0.3 to 1 s); `wasm` builds with wasi-sdk (pinned version, downloaded and cached) and runs `web/smoke.mjs` extended to the same 60 seeds in Node; `compare` normalises CRLF, sorts, diffs every platform against GCC, then against the first 60 lines of `tests/golden/state_hashes.txt`, and uploads traces on failure. `concurrency` with `cancel-in-progress`. Start with GCC + MSVC + compare and add Clang and wasm once green. `hoard-nightly.yml` (cron and manual): the full 300-seed golden on all four platforms, `sanitize` (ASan + UBSan with `-fsanitize=float-cast-overflow,float-divide-by-zero -fno-sanitize-recover=all`, 1,000 seeds × 1000 years), `interest` (300 seeds, artifact 30 days), `perf` (cachegrind instruction count of one 3000-year seed against `tests/perf.json`, fail at +5 %; wall time reported), `replays`, `saves`. `hoard-web.yml` on pull requests touching `games/hoard/web/`: Playwright in Chromium, Firefox and WebKit running `web/check.cjs` and `web/game-check.cjs` on one worker with `retries: 1`; the wasm hash compared with native in all three. No Unreal in hosted CI.
8. **Negative controls.** Before merging: build the golden runner with `-march=haswell -ffp-contract=fast` and confirm hashes move (if none moves, add a float-heavy case and say so); run `compare` once with one platform's file altered and once with the golden altered and confirm two failures.
9. **Docs in the repo.** `games/hoard/CLAUDE.md` gains the determinism policy in ten lines, the golden rule, the branch and report conventions, and the build and test commands including wasm. `README.md` gains "how to replay a bug report".
10. **`dragons[]`.** `World.dragon` becomes `World.dragons` (a vector, index 0 the player) in its own commit, with serialisation reading old saves; preamble rule 8.

Out: fuzzing targets (write the three shapes from the research §5 into `tests/fuzz/README.md`, no code), bank pinning (item 10), the UE module (item 18), telemetry upload (phase 5), any rule change beyond the `pow` replacement.

## Design notes

- `/fp:strict` and `-ffp-contract=off` cost little at the measured speed; do not argue for faster flags.
- Expect exactly one golden regeneration (own `pow`), in its own `golden:` commit with the chronicle diff of the three text seeds, after every CI platform printed the same new hashes. The `dragons[]` commit must not move any hash.
- Hash values, never memory; padding is uninitialised. Value-initialise every state struct while you are in there.
- wasi-sdk, not Emscripten; pin the version in CI and in `README.md`. Extend `web/smoke.mjs`, do not replace it.
- Files stay short and one job each: `hash.h`, `detmath.cpp`, `trace.cpp`, `save_header.cpp`, `migrate.cpp`, `replay.cpp`, `fp_env.cpp`.
- Local runs: `-j` at the core count; 60 seeds while iterating, 300 once before the golden commit.

## Acceptance

- `hoard-ci.yml` green on GCC, Clang, MSVC and wasm with `compare` passing; the two negative controls documented in the report with their failing output.
- `tools/check_banned.sh` passes on `sim/`; `grep -rn "std::pow\|std::exp\|std::log" sim/` is empty outside `detmath.cpp`.
- `hoard-sim record` then `replay --verify` passes for `played`, `idle` and `raze_all` on seeds 1 to 10, including runs that use `pick_talent`, `answer_hook` and offers; a replay with one magnitude edited by hand fails at the following checkpoint with exit code 3.
- `--trace` on two builds that differ gives `first_div.py` a first differing decade and part.
- A save written by the build loads and recomputes its hash; a save with a flipped byte is refused with the autosave offered.
- The six existing tests pass; the golden regeneration is one `golden:` commit.
- `ctest -L fast` under 60 s; `hoard-ci.yml` under 15 minutes.

## Proposed tests (confirm with the owner first)

`banned_ops` (the grep gate), `hash_canonical` (−0 and +0 hash equal; NaN changes the hash; same elements in sorted iteration hash equal), `rng_sequence` (fixed `world.rng` and `rng_for` sequences), `save_roundtrip` (write, load, hash equal; flipped byte refused), `replay_verify` (record and replay seeds 1 to 3; edited input fails), `detmath_bounds` (own `pow`, `exp`, `log` within the stated relative error on 10,000 inputs). All labelled `fast`.
